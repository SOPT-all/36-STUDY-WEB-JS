### 42장 비동기 프로그래밍

### 동기 처리와 비동기 처리

실행 컨텍스트 스택

- 함수가 호출되면 실행 컨텍스트가 생성되어 스택에 푸시됨
- 실행이 끝나면 팝되어 제거됨
- 자바스크립트 엔진은 하나의 실행 컨텍스트 스택만 가지므로 **한 번에 하나의 작업만 실행 가능**함
- 이 구조 때문에 JS는 **싱글 스레드** 방식으로 동작함

동기 처리

- 태스크가 순서대로 하나씩 처리됨
- 실행 순서가 보장됨
- 앞의 작업이 끝나기 전까지 다음 작업은 대기해야 함 (블로킹 발생)

### 비동기 처리

- 현재 작업이 끝나지 않아도 다음 작업을 바로 실행함
- 블로킹이 발생하지 않음
- 실행 순서는 보장되지 않음

```jsx
setTimeout(foo, 3000);
bar();
```

- `foo`는 3초 후 콜백 큐에 들어가 실행됨
- `bar`는 즉시 실행됨

### 이벤트 루프와 태스크 큐

### 싱글 스레드와 동시성

- 자바스크립트는 싱글 스레드지만 브라우저는 멀티 스레드 환경임
- 브라우저가 자바스크립트 엔진 외에도 Web API, 렌더링 엔진 등을 통해 **동시성**을 지원함

### 콜 스택과 힙

- **콜 스택**: 실행 컨텍스트가 들어가 순차적으로 실행됨
- **힙**: 객체가 저장되는 메모리 공간임 (동적으로 크기가 결정됨)

### 태스크 큐(Task Queue)

- setTimeout, setInterval, 이벤트 핸들러 등의 **콜백이 일시 보관**되는 영역
- FIFO(First In, First Out) 방식으로 큐에 보관됨
- 마이크로태스크 큐는 따로 존재하며 프로미스 후속 처리 등에 사용됨 (45장에서 설명)

### 이벤트 루프(Event Loop)

- **콜 스택이 비었는지 확인하고**, 태스크 큐에 작업이 있으면 실행함
- 즉, 큐에 있는 콜백 함수는 **콜 스택이 비어야 실행됨**
- 자바스크립트 엔진은 큐를 직접 다루지 않고, 이벤트 루프가 이를 담당함

### 브라우저와 자바스크립트의 협업

### 자바스크립트 엔진은 싱글 스레드지만, 브라우저는 멀티 스레드임

- setTimeout의 타이머 설정 및 콜백 큐 등록은 브라우저(Web API)가 담당함
- 콜백의 평가 및 실행은 JS 엔진이 처리함

### setTimeout 처리 과정

1. 전역 실행 컨텍스트 생성
2. `setTimeout(foo, 0)` 호출 → 타이머 설정 (Web API)
3. `bar()` 실행 → 콜 스택에서 실행됨
4. 타이머 만료 후 콜백(`foo`)이 **태스크 큐에 등록됨**
5. 전역 컨텍스트가 끝나고 콜 스택이 비면 → 이벤트 루프가 큐의 `foo`를 콜 스택으로 이동시켜 실행
