## 41장 타이머

### 호출 스케줄링

- 명시적으로 호출된 함수는 즉시 실행됨
- 일정 시간 후에 함수를 실행하려면 **타이머 함수**를 사용함
- 이를 **호출 스케줄링**이라 함
- `setTimeout`, `setInterval`은 타이머를 생성하고, `clearTimeout`, `clearInterval`은 타이머를 제거함
- 타이머 함수는 ECMAScript 내장 함수가 아니라 **호스트 객체 API**임 (브라우저, Node.js에서 제공)
- JS는 싱글 스레드 환경이므로 타이머는 **비동기적으로 동작함**

### 타이머 함수

### setTimeout / clearTimeout

- `setTimeout(fn, delay, ...params)`
  - 일정 시간 `delay` 후 `fn`이 **단 한 번 실행됨**
  - `delay`는 ms 단위이며, 생략하면 기본값 0임
  - `delay`가 4ms 이하이면 실제로는 최소 4ms로 강제됨 (HTML5 표준)
  - IE9 이하에서는 콜백에 인수 전달 불가능

```jsx
setTimeout(() => console.log("Hi!"), 1000);
setTimeout((name) => console.log(`Hi! ${name}`), 1000, "Lee");
```

- `setTimeout`은 타이머 ID를 반환함
- `clearTimeout(timerId)`로 해당 타이머 취소 가능
- 취소되면 콜백은 호출되지 않음

### setInterval / clearInterval

- `setInterval(fn, delay, ...params)`
  - 일정 시간 간격으로 `fn`을 **반복 실행함**
  - 종료 시점이 없으며, 명시적으로 취소하지 않으면 계속 반복됨
- `clearInterval(timerId)`로 타이머 취소 가능
- 브라우저에선 숫자, Node.js에선 객체를 ID로 반환함

```jsx
let count = 1;
const id = setInterval(() => {
  console.log(count);
  if (count++ === 5) clearInterval(id);
}, 1000);
```

### 디바운스와 스로틀

- `scroll`, `resize`, `input` 등의 이벤트는 매우 자주 발생함
- 이런 이벤트에 바인딩된 핸들러는 과도하게 호출되어 성능 저하를 일으킬 수 있음
- 이를 완화하기 위한 기법이 **디바운스(debounce)**와 **스로틀(throttle)**임

### 디바운스 (debounce)

- 연속해서 발생하는 이벤트 중 **마지막 한 번만** 실행되도록 함
- delay 시간 안에 다시 이벤트가 발생하면 타이머를 초기화하고, delay 시간 내에 더 이상 발생하지 않으면 콜백 실행됨
- 사용 예: 자동완성, Ajax 요청 최적화, 버튼 중복 클릭 방지 등
- 실무에서는 **Underscore.js** 또는 **Lodash**의 `debounce` 함수 사용 권장함

### 스로틀 (throttle)

- 연속해서 발생하는 이벤트를 **일정 간격(delay)마다 한 번만** 실행되게 제한함
- delay 시간 이전에 이벤트가 발생해도 무시되고, delay 이후에 다시 이벤트가 발생하면 실행됨
- 사용 예: 스크롤 이벤트 처리, 무한 스크롤 UI 등

```jsx
const throttle = (callback, delay) => {
  let timerId;
  return (event) => {
    if (timerId) return;
    timerId = setTimeout(() => {
      callback(event);
      timerId = null;
    }, delay);
  };
};

container.addEventListener(
  "scroll",
  throttle(() => {
    throttleCount.textContent = ++count;
  }, 100)
);
```

- 실무에서도 마찬가지로 **Underscore.js** 또는 **Lodash**의 `throttle` 함수 사용 권장함
