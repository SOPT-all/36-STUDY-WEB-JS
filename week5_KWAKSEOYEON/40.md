## 40장 이벤트

### 이벤트 핸들러

- 애플리케이션이 특정 타입의 이벤트에 반응하여 어떤 일을 하고 싶다면 해당하는 타입의 이벤트가 발생했을 때 호출될 함수를 브라우저에게 알려 호출을 위임한다. 이때의 **이벤트가 발생했을 때 브라우저에 의해 호출될 함수**를 이벤트 핸들러라고 한다.
- 함수를 언제 호출할지 알 수 없으므로 브라우저에게 함수 호출을 위임하는 것이다.

### 이벤트 드리븐 프로그래밍(event driven programming)

- 프로그램의 흐름을 이벤트 중심으로 제어하는 프로그래밍 방식

### 이벤트 타입

- 이벤트 종류를 나타내는 문자열이다.
- 예를 들어 click은 사용자가 마우스 버튼을 클릭했을 때 발생하는 이벤트
- 이벤트 타입

### 이벤트 핸들러 등록

1. 이벤트 핸들러 어트리뷰트 방식

- 이벤트 핸들러 어트리뷰트 이름은 onClick과 같이 접두사와 이벤트 타입으로 이루어져 있다.
- 이벤트 핸들러 어트리뷰트 값으로 statement를 할당하면 이벤트 핸들러가 등록된다.
- 주의할 점은 핸들러 어트리뷰트 값으로 함수 참조가 아닌 함수 호출문 등의 문을 할당한다는 것이다.

1. 이벤트 핸들러 프로퍼티 방식

![image.png](attachment:399f4c47-3d6c-4d21-bb3c-94a4e4db136a:image.png)

- window 객체와 Document HTMLEIement 타입의 DOM 노드 객체는 이벤트에 대응하는 이벤트 핸들러 프로퍼티를 가지고 있다. 이 방식은 이벤트 핸들러 프로퍼티에 이벤트 핸들러를 바인딩한다.
- 이 방식은 1번 방식에서 HTML, 자바스크립트가 뒤섞이는 문제를 해결할 수 있다.
- 하지만 이벤트 핸들러 프로퍼티에 하나의 이벤트 핸들러만 바인딩할 수 있다는 단점이 있다.

1. addEventListener 메서드 방식

![image.png](attachment:cde037ab-406a-4ec2-b9f1-0444d9f071f7:image.png)

- 이벤트 핸들러를 인수로 전달한다.
- 하나 이상의 이벤트 핸들러를 등록할 수 있고, 이들은 등록된 순서대로 호출된다.
- 단, 메서드를 통해 참조가 동일한 이벤트 핸들러를 중복 등록하면 하나의 이벤트 핸들러만 등록된다.

### 이벤트 핸들러 제거

- addEventListener 메서드로 등록한 이벤트 핸들러를 제거하려면 EventTarget.prototype.removeEventListener 메서드를 사용한다. 전달 인수는 동일하다.
  - 그렇기 때문에 무명 함수를 이벤트 핸들러로 등록한 경우 제거할 수 없다.
  - 이벤트 핸들러를 제거하려면 이벤트 핸들러의 참조를 변수나 자료구조에 저장하고 있어야 한다.
  - 가급적 이벤트 핸들러의 참조를 변수나 자료구조에 저장하여 제거하는 편이 좋다!

### 이벤트 객체

- 이벤트가 발생하면 이벤트에 관련한 다양한 정보를 담고 있는 이벤트 객체가 동적으로 생성된다.
- 생성된 이벤트 객체는 이벤트 핸들러의 첫 번째 인수로 전달된다. → 매개변수 e에 암묵적으로 할당된다.
- 브라우저가 이벤트 핸들러를 호출할 때 이벤트 객체를 인수로 전달하기 때문이다!
- 이벤트 객체를 전달받으려면 이벤트 핸들러를 정의할 때 이벤트 객체를 전달받을 매개변수를 명시적으로 선언해야 한다.

![image.png](attachment:96a67b48-84b6-4158-b3c6-05f0a9d2e616:image.png)

- 이벤트가 발생하면 이벤트 타입에 따라 이벤트 객체가 생성되며 이벤트 객체는 다음과 같은 상속 구조를 갖는다.

### 이벤트 전파

- DOM 트리 상에 존재하는 요소는 DOM 트리를 통해 전파되며 이를 이벤트 전파라고 한다.

![image.png](attachment:df0c9316-a45e-4f0f-8196-d3a2dbc9a80f:image.png)

- 생성된 이벤트 객체는 이벤트를 발생시킨 돔 요소의 이벤트 타킷 중심으로 DOM 트리를 통해 전파된다.
- 캡쳐링 단계 (이벤트가 상위 요소에서 하위 요소로 전파) → 타깃 단계 (이벤트가 이벤트 타깃에 도달) → 버블링 단계(이벤트가 하위 요소에서 상위 요소로 전파)

### 이벤트 위임 (Event Delegation)

- 여러 하위 요소에 이벤트 핸들러를 각각 등록하는 대신, **상위 요소 하나에만 이벤트 핸들러 등록**해서 하위 요소의 이벤트를 처리하는 방식임
- ~~내비게이션 아이템 100개에 이벤트 핸들러를 각각 등록하면 비효율적~~이라 상위 요소 하나에 위임하는 방식이 유리함

주의할 점

- `target`은 실제 이벤트가 발생한 하위 요소이고, `currentTarget`은 이벤트 핸들러가 바인딩된 상위 요소임
- `Element.prototype.matches` 메서드를 이용해 원하는 하위 요소인지 체크 필요

### DOM 요소의 기본 동작 조작

기본 동작 중단

- `preventDefault()` 사용
- 예: `a` 클릭 시 링크 이동 방지, `checkbox` 체크 방지 등

이벤트 전파 방지

- `stopPropagation()` 사용
- 이벤트가 상위로 전파되지 않도록 막음
- 예: `btn2` 버튼만 클릭 이벤트 자체적으로 처리하고 상위에 전달하지 않음

### 이벤트 핸들러 내부의 this

이벤트 핸들러 어트리뷰트 방식 (`onclick="handler()"`)

- `this`는 전역 객체 `window`를 가리킴

핸들러에 `this` 전달 시

- `onclick="handler(this)"` 처럼 작성하면 전달한 DOM 요소를 가리킴

이벤트 핸들러 프로퍼티 방식 / `addEventListener` 방식

- 핸들러 내부의 `this`는 이벤트를 바인딩한 **DOM 요소**를 가리킴
- `this === e.currentTarget` → `true`

화살표 함수 사용 시 주의

- 화살표 함수는 자신만의 `this`를 갖지 않아서, 상위 스코프의 `this`를 사용함
- 대부분 `window`를 가리켜서 원하는 결과가 안 나올 수 있음

클래스에서 this 문제

- `this.method.bind(this)`로 바인딩하거나
- 클래스 필드에 화살표 함수로 정의 (`increase = () => {}`)하면 해결 가능

### 커스텀 이벤트

커스텀 이벤트 생성

- `new Event('type')`, `new MouseEvent('click')`, `new CustomEvent('foo')` 등 사용
- `isTrusted` 값은 항상 `false`임 (사용자 동작이 아닌 인위적으로 발생시킨 이벤트라서)

커스텀 이벤트에 속성 추가

- 두 번째 인수로 `{ bubbles: true, cancelable: true, detail: { ... } }` 전달 가능

### 커스텀 이벤트 디스패치

- `element.dispatchEvent(customEvent)`로 이벤트 발생시킴
- 디스패치는 **동기적으로 실행**됨
- 커스텀 이벤트를 처리하려면 **반드시 `addEventListener` 방식**으로 등록해야 함
  (`onfoo` 같은 어트리뷰트 방식은 지원되지 않음)
